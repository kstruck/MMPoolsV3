## 2. The open PR — PLAN-PAYMENT-LEDGER **T2**

**Blast radius: the browser bundle only.** No `functions/` change, no
`firestore.rules` change, no index change, no prod-data mutation. The server
side of `weeklyPayouts` shipped in T1 and is already live; T2 is the UI that
finally lets a commissioner write it.

What it does (D2, plus D1's transition notice):

1. **Wizard.** `StepPayouts` renders its places editor **twice on HYBRID** —
   "Weekly prizes — % of the weekly pot" bound to `settings.weeklyPayouts`, and
   "Season prizes — % of the season pot" bound to `settings.payouts`. WEEKLY and
   SEASON still render **one** editor bound to `settings.payouts`, exactly as
   before: `weeklyPayouts` is HYBRID-only and every other mode reads `payouts`.
   Live "must not exceed 100 %" **and** a duplicate-rank line per editor, using
   the same `uniqueRanks` predicate the schema enforces.
2. **`buildNFLPayload`.** A weekly list survives only on a HYBRID pool — the
   same guard `hybridSplit` already has, for the same reason: react-hook-form
   keeps the values of unmounted fields, so a commissioner who tried HYBRID,
   typed places, then settled on SEASON would otherwise submit a list the create
   schema refuses from a screen where the editor is gone. An **empty** list is
   dropped too: absent means "`payouts` prices both pots" (today's behaviour),
   while a stored `{ places: [] }` would mean "no weekly prizes at all".
3. **Manager Settings** (`NFLManagerView`, Pick'em and Margin) gets the same
   editor under the HYBRID split, and sends `weeklyPayouts` only on a HYBRID
   save — the T1 callable validates it and deletes it on the way out of HYBRID.
   Leaving HYBRID clears it locally; returning re-hydrates from the last
   known-stored list, never the lagging realtime prop.
4. **HYBRID exit notice (D1).** While the stored mode is HYBRID and the selected
   one is not, manager Settings says so before the save — on HYBRID → WEEKLY the
   SEASON places silently become the list that prices every week, which is a
   money change nobody asked for.
5. **`PayoutsPanel`** prices each pot from **its own** list via
   `weeklyPlacesFor(settings)`. The #423 example now renders a $180 weekly pot
   at 60/40 ($108/$72) and a $70 season pot at 100 % ($70) instead of one
   combined line. Bonuses print against the season pot, not both.

## 4. K9 census — ANSWERED 2026-08-17: it was NOT run

Kevin skipped `functions/scripts/censusPayoutRanks.mjs` before merging **#470**.
The runbook step said *"skip if you have no service-account key"*, he had none,
so he skipped it and went on. So T1's unique-rank refinement shipped with the
duplicate-rank count on existing pools **unknown**, not zero.

**What that exposes today: nothing reachable.** Three paths could hit the
season-list refusal (`PAYOUT_DUPLICATE_RANK` on `settings.payouts`), and all
three are closed:

1. **The manager save.** `updatePoolSettings` has exactly ONE caller in the app
   — `NFLManagerView.handleSaveSettings` — and it never sends `settings.payouts`.
   It sends `payoutMode`, `hybridSplit` and (new in T2) `weeklyPayouts`, never
   the season list. The gate is judged only `if ('settings.payouts' in patch)`,
   so a legacy duplicate-rank pool is not refused.
2. **Create.** A new pool cannot carry duplicates — the schema refuses them, and
   T2's editors will not mint one (`+ Add place` takes one past the highest rank).
3. **A direct client write.** T1 put `payouts` in the NFL-only
   `callableOnlySettingsUnchanged()` clause, so a client writing
   `settings.payouts` on an NFL pool is denied by rules.

`AdminPanel`'s `payouts` is the Squares quarterly map (`q1/half/q3/final`), a
different shape entirely — not `settings.payouts.places`.

**Where it becomes real.** The moment anything adds a SEASON-places editor to
the manager UI — a natural follow-up to T2, which only added the weekly one — a
legacy duplicate-rank pool becomes unsavable, and there would be no UI to fix
the list it is refused for. Run the census before that ships, not after.

**How to actually run it** (needs prod read credentials; the script never writes):

1. Firebase Console → Project settings → **Service accounts** → **Generate new
   private key** → save the JSON somewhere outside the repo.
2. From the repo root:
   `$env:GOOGLE_APPLICATION_CREDENTIALS = "C:\keys\mmp-census.json"`
   then `node functions/scripts/censusPayoutRanks.mjs`
3. Expect `scanned N pools; 0 with duplicate ranks`. Any hit prints the pool id.
4. Delete the key file afterwards.

The script also accepts `gcloud auth application-default login` credentials in
principle, but its own guard requires `GOOGLE_APPLICATION_CREDENTIALS` to be set,
and `gcloud` is not installed on this machine — so the key-file route is the
only one available today.
