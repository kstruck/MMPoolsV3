### [#314](https://github.com/kstruck/MMPoolsV3/pull/314) — reminder delivery outcomes

**What it does.** `runReminders` counted only pools whose handler *threw*.
`sendEmail` caught its own queue failures, `sendCourierSMS` returned a boolean
nobody read, and `checkNFLNonPickerReminders` swallowed its own errors — so a
run where every email failed to queue reported zero failed pools and a healthy
heartbeat. `lib/deliveryTally.ts` counts queued / skipped / failed / poolErrors,
and `reminderPassVerdict` grades them. **`skipped` (no address, unsubscribed,
opted out, SMS not configured) is reported and deliberately never graded** — the
crying-wolf rule.

**⚠️ THIS PR CONTAINS ONE OUTWARD BEHAVIOUR CHANGE — decide before merging.**
`runReminders` now binds `COURIER_AUTH_TOKEN`. Gen-2 functions see only the
secrets they bind, and this job bound none, so **every SMS reminder it has ever
tried to send silently was not sent.** The secret already exists (userManagement
binds it), so this adds no deploy prerequisite — but on deploy, SMS reminders
start actually going out to members with a phone number who have opted in.

- If you want that: merge as is.
- If you do not want it yet: tell me and I will drop the one option; the job
  keeps working, minus SMS. Everything else in the PR stands either way.
