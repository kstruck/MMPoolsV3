### Why it had never been run

`goldenArc.emulator.test.ts` certifies the real member-action paths end to end,
and **every pool and every game in it is `seasonType 2`** (regular season). The
pilot opens on `seasonType 1`. Two other suites do use preseason, but only for
scheduled-job paths — **create → join → pick → lock → score → recap → finalize
had never once been executed on a preseason slate.**

Preseason is not regular season with a different number in a field:

- **HOF week is a ONE-GAME week.** Every other week the code has been exercised
  against has 13–16. Confidence ranges, survivor team pools and margin team
  reuse all key off slate size.
- **Preseason and regular season share week NUMBERS.** Preseason week 2 (the
  08-13 slate) and regular week 2 both exist in `nfl_games`.
- **`seasonType` is optional on a pool, and unset means REGULAR.**

### What was exercised — 21 tests

Pick'em (join → per-game lock → score → **weekly recap** → **member-readable
standings** → finalize → zero-residue cleanup), confidence mode, Survivor,
Margin, cross-`seasonType` contamination, and the unset-`seasonType` pool.

I asserted the recap and standings because **"Score & Recap Week N" is your
actual HOF-night button** — asserting the entry score alone would pass while
members saw an empty leaderboard.

### Two things worth knowing — neither is a bug

**On a one-game week the only legal confidence value is 16, not 1.** The range
is computed as `[17 − N .. 16]`, anchoring the top at 16 rather than the bottom
at 1. For a 16-game week that is the familiar 1..16; on HOF night it means 16 is
the only value the server accepts.

Not a defect — the client computes the identical range, so nothing gets
rejected. I checked it deliberately: **a client offering 1..N against a server
demanding 16..16 would have failed every confidence submission on HOF night.**

**Every pool-scoped server query already filters on the pool's `seasonType`** —
verified across six files. The #319 fix is applied consistently server-side.

### The rehearsal's own hole, found by self-review

Codex passed it clean. Reading it myself found a **vacuous assertion** (it
checked a field that only the *bracket* scorer writes, so it could never fail),
and chasing that exposed a real gap: `nflPools.ts` has **two independent
`seasonType` filters** — submit and the scorer — and deleting **only the
scorer's** left the whole suite green. A leak confined to the scorer is
invisible in every entry field, because unpicked games are never graded. It
would still be wrong: the scorer's slate is what decides whether a week is fully
final. Now covered by its own test.
