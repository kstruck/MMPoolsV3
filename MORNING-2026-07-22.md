## 7. What I did overnight, and one mistake I caught

Four PRs, one at a time, each with all five gates plus a codex review round.

| PR | What | Needs deploy? |
|---|---|---|
| [#255](https://github.com/kstruck/MMPoolsV3/pull/255) | BANNED owner rejected on 3 ownership-path callables | **Yes** |
| [#256](https://github.com/kstruck/MMPoolsV3/pull/256) | Heartbeat verdicts extracted + unit-tested | Yes |
| [#257](https://github.com/kstruck/MMPoolsV3/pull/257) | Emulator coverage: finalize sweep + replay | No |
| [#254](https://github.com/kstruck/MMPoolsV3/pull/254) | fast-uri bump, security-audit green (merged) | No |

Test counts moved: functions vitest 913 → 940, emulator 105 → 123.

**A mistake I made, then made worse, before codex caught it.**

I built PR #255 on a branch cut from a stale base. `git diff origin/main..HEAD`
showed a 125-line `package-lock.json` reversal, and I concluded the PR would
revert the `fast-uri` security fix from #254. I rebuilt the branch and wrote that
conclusion into this document and into `CLAUDE.md` as a new standing rule.

**It was wrong.** Codex reviewed the write-up and pointed out that a two-dot diff
compares branch *tips*, so anything `origin/main` gained after I branched shows
as a reverse change. I checked rather than argued: no commit on that branch ever
touched `package-lock.json`, and the three-dot diff
(`git diff origin/main...HEAD -- package-lock.json`) is **empty**. Git's
three-way merge would have preserved the fix. The PR was fine; the diff command
was wrong, and so was the alarming story I built on it.

The branch rebuild was still worth doing - it kept eight unrelated commits out of
the PR's history - but that is tidiness, not a save.

What I am actually taking from it: **a scary reading of a command's output is a
hypothesis, not a finding.** I should have run
`git log origin/main..HEAD -- package-lock.json` before believing it, and
certainly before promoting it to a standing rule. `CLAUDE.md` §2c now carries the
corrected version, with the three-dot form.
