## Goal

Make every Pool type (SQUARES, BRACKET, NFL_PICKEM, NFL_SURVIVOR, NFL_MARGIN, NFL_PLAYOFFS, PROPS) provably work end to end for Members, Commissioners, and the Super Admin before NFL pre-season, and rebuild the Super-Admin dashboard into one coherent 8-tab system where every control is real, every capability lives in exactly one place, and every destructive action has an explain-then-confirm guardrail with an Admin Audit Log entry.

## Key decisions & tradeoffs

- **Flags live in `system/config` (existing doc), not a new collection** — already rules-protected (SUPER_ADMIN write), already push-subscribed client-side; server reads 1 doc per create call. Rejected: env-based flags (no runtime toggle), per-flag docs (needless reads).
- **Server-side flag/lifecycle checks are authoritative; UI checks are UX only.** Consistent with the existing trust boundary (rules + callables).
- **Fail-open flag defaults** — a missing/corrupt config doc must never brick pool creation; defaults mirror current launch posture.
- **Delete fake cards rather than build real equivalents where no real backend exists** (vulnerability scanner, schema-backfill console); honesty over feature count. Real equivalents live in Operations (backfill) and Test Suite (tests).
- **Sim isolation via `isSimulation` flag + `sim-` slug namespace** rather than a separate Firestore project — cheaper, uses existing rules hook (`firestore.rules` sim-slug create rule); tradeoff: requires guards inside every trigger/side-effect path (not just query filters), which is why trigger guarding is a hard prerequisite of T12 with an emulator test proving zero mail/stats leakage; if guard coverage proves unmaintainable, fall back to emulator-only runs for the harness.
- **Health data flows through one privileged callable (`getAdminHealthSnapshot`)**, not client-side probes — client cannot read `mail`, and one typed payload beats N one-off rule escapes.
- **`closePool` extends the existing exception/lifecycle layer** (`poolExceptions.ts`) with the repo-standard `ownerId || managerUid || SUPER_ADMIN` principal — no parallel lifecycle path.
- **Role model adopts CONTEXT.md's five roles now** (code currently has three) to avoid re-migrating claims twice; PLAN-USER-MGMT.md already specs it.
- **Keep CSR + prerender + nginx bot-proxy for SEO** — adequate post-Phase-0 fixes; no SSR migration this cycle.

## Risks / open questions

- Auto-close sweep mis-closing a live pool → dry-run mode first week + kill-switch + per-type end-date logic reviewed against real schedules. **UNVERIFIED in this environment:** which specific prod pools are stuck open and their field states — first implementation step is a read-only prod query to confirm the per-type close conditions.
- Playoff entries migration touches live data → dry-run, copy-test, fallback read path until verified.
- `enforceAppCheck` may lock out legitimate clients if rolled out un-staged → log-only/staged rollout.
- Prod Gemini/Stripe secret state unverifiable from repo → smoke-check buttons in Test Suite report real call results.
- Five-role migration: existing `POOL_MANAGER`/`PARTICIPANT` values must map (COMMISSIONER/MEMBER) without breaking rules or UI badges — migration script + dual-read window.
