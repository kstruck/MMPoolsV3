### ⚠️ One thing to brace for, because it lands the night before the game

The first successful run **can send email.** About 4 pools move
`trial → grace_period`, and each transition *attempts* one commissioner email —
all of them yours. Nothing can lock: no pool sits in `grace_period` today, so
phase 2 has no candidates for another 7 days. If four "your pool enters its
grace period" emails at 23:00 the night before the HOF game is not what you
want, the time to say so is today.

⚠️ **"Can", not "will" — and a run that sends ZERO emails is still a clean run.**
The send sits in its own `try`/`catch` nested *inside* the per-pool one
(`functions/src/billing.ts:148-171`), so neither a missing address nor a mail
failure counts as a failed transition:

- `resolveCommissionerEmail` (`billing.ts:64`) returns `string | null`; on `null`
  the code logs `No commissioner email found for pool …; skipping` and moves on.
- A `sendEmail` throw is caught and logged as
  `Failed to send grace-period email for pool …` — the billing-status write has
  already committed by then.

So **do not treat "I got no emails" as evidence the job failed.** The Ops Health
line is the verdict; the emails are a side effect. If the transitions happen and
the emails do not, the answer is in the function logs, not the heartbeat.

### 3.3 What happens if you score it before the game is FINAL

**You are SUPER_ADMIN, so the guard does not stop you — and that is fine now,
because the code handles it deliberately.**

- The gate: `ACTIVE_GAMES: Cannot score the week while N games are still active`
  — thrown at `functions/src/nflPools.ts:1536-1538`, **and only when
  `userRole !== 'SUPER_ADMIN'`.** A regular commissioner is blocked; you are not.
- What protects you instead is the `provisional` flag, which is **derived, not
  hard-coded** (`:1552`): `provisional: !isWeekComplete(pool, week, games, now)`.
- On a provisional pass the scorer withholds exactly the things that would be
  wrong mid-week: no Survivor strikes or Margin `-14`s applied from
  un-concluded games, no `scoredWeeks` marker, no `maybeFinalizeNFLPool`, no
  weekly recap, no `SCORE_FINALIZED` audit. `standings/current` IS written —
  live standings are the point (`:899-911`).
- The message you get back is
  `Week N scored provisionally — live standings updated.` (`:1478`).

**So: an early click is safe and reversible, and it says so.** It is still not
what you want — **wait until the game shows FINAL**, then click once. The message
