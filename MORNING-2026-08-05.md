### 3.2 🔄 Idempotency — the standing warning is OUT OF DATE

**Survivor scoring IS idempotent now. You may click Score twice.** I am
contradicting the note that has been carried forward for a month, so here is the
evidence rather than the assertion.

- The old danger was `newStrikes = entry.strikesUsed + (strikeLogged ? 1 : 0)`.
  **That line no longer exists** — `grep -n "strikesUsed" functions/src/nflPools.ts`
  returns only `strikesUsed: 0` at entry creation and at rebuy reset.
- Strikes are now recomputed from a ledger.
  `computeSurvivorWeekUpdate` (`functions/src/nflScoringEngine.ts:494`) keeps
  `strikeWeeks: number[]`, drops the current week from the prior list
  (`:517`) and re-derives `strikesUsed = strikeWeeks.length` (`:547`). Scoring
  week N twice produces the same answer both times.
- It was fixed on **2026-07-07** by `248f61a`,
  *"fix(nfl): dual-MNF combined tiebreaker + idempotent scoreNFLWeek survivor
  rescoring"* — one day after the skill that carries the old warning was written.
- There is a suite whose `describe` is literally
  `computeSurvivorWeekUpdate — idempotency`. I ran it:
  ```bash
  npm --prefix functions test -- src/__tests__/survivorRescore.test.ts
  ```
  → **8 passed**.
- A second concurrent pass is separately protected: a live pass takes a **fenced
  scoring lease** for the whole pool and a pass that finds it held returns
  `leaseBusy: true` having read and written nothing
  (`functions/src/nflPools.ts:913-951`).

⚠️ **One carve-out, and it cannot bite you on Thursday.** The engine's own comment
(`nflScoringEngine.ts:489-490`) notes that a legacy entry carrying `strikesUsed`
with no `strikeWeeks` ledger loses those unattributed strikes on its first
rescore. The HOF game is week 1 of a fresh season type with no prior strikes
anywhere, so there is nothing to lose. It matters later, not now.

Pick'em and Margin were always idempotent (whole-map overwrite + re-derive).

### 3.3 What happens if you score it before the game is FINAL

**You are SUPER_ADMIN, so the guard does not stop you — and that is fine now,
because the code handles it deliberately.**

- The gate: `ACTIVE_GAMES: Cannot score the week while N games are still active`
  — thrown at `functions/src/nflPools.ts:1536-1538`, **and only when
  `userRole !== 'SUPER_ADMIN'`.** A regular commissioner is blocked; you are not.
- What protects you instead is the `provisional` flag, which is **derived, not
  hard-coded** (`:1552`): `provisional: !isWeekComplete(pool, week, games, now)`.
- On a provisional pass the scorer withholds exactly the things that would be
  wrong mid-week: no Survivor strikes or Margin `-14`s applied from
  un-concluded games, no `scoredWeeks` marker, no `maybeFinalizeNFLPool`, no
  weekly recap, no `SCORE_FINALIZED` audit. `standings/current` IS written —
  live standings are the point (`:899-911`).
- The message you get back is
  `Week N scored provisionally — live standings updated.` (`:1478`).

**So: an early click is safe and reversible, and it says so.** It is still not
what you want — **wait until the game shows FINAL**, then click once. The message
you want to see is the non-provisional one.

**If you click and get** `Another scoring pass is already running for this pool;
nothing was written.` — that is the lease, not an error. Wait a moment and click
again.
