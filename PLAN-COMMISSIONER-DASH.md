# Plan: Commissioner Dashboards + Member Pool Homepage overhaul
_Locked via grill-with-docs — by Claude + Kevin. Terms per CONTEXT.md. Architecture per ADR 0003._

## Goal
Make every commissioner and member surface honest, consistent, and world-class before preseason live testing. No card shows a number it cannot prove. A Commissioner sees a real Roster of every Member (including themselves) with real Paid Status and honest Dues figures; a Member sees a single Pool Homepage that shows only the cards that apply to that Pool's type. Nav means what it says: "Manage My Pools" goes to the Commissioner Hub, "My Entries" lists the Pools you play in. Membership and payment run on one Member Record per Member roster model (ADR 0003) across all Pool types.

## Approach

Ordered by preseason priority. Phase 1 + 2 are the must-ship set; Phase 3 is the redesign; Phase 4 is polish. Everything is UI/client + Cloud Functions authored and **staged** — no prod function deploy or prod migration run overnight (see Out of scope).

### Phase 1 — Honesty & correctness quick wins (highest priority, low risk)
1. **Split the nav.** `Header.tsx` — "Manage My Pools" navigates to the Commissioner Hub (Roster Hub with the `commissioner` tab active); "My Entries" navigates to a member-entries view (Pools the User is a Member of, not owner). Distinct destinations; keep both only when the User is a Commissioner.
2. **Kill the fake stat cards.** In `ParticipantDashboard.tsx`/`GlobalCommissionerDashboard.tsx`, stop reading the never-written `user.managerStats` blob. Until the aggregate function lands (Phase 2), compute the four figures client-side from already-subscribed pools + entries, or hide any figure that can't be proven. Relabel "Prize Payouts" (currently a count of winning squares) and fix "Active Entries"/"Net Winnings" so they count all Pool types, not only Squares/Bracket/Playoff.
3. **Fix the Live Weekly Pick'em card.** `NFLUserBentoDashboard.tsx` — render the week's slate (map the `weekly` array), not a single `focusGame`; keep a highlighted focus game but list the rest. Move the Live/Scheduled status badge off `absolute top-2 left-2` so it stops covering the away-team logo.
4. **Type-gate the Pool Homepage cards.** Survivor Attrition renders only on `NFL_SURVIVOR`, Margin Pool Stats only on `NFL_MARGIN`, etc. Introduce a small `poolType` classifier util (there is none today — all string `===`) and gate each card by it.
5. **Type-gate the pool-page sidebar.** Same file — replace the hardcoded `[Dashboard, Pick'em, Survivor, Margin, Rules]` array with links appropriate to `pool.type` (a Pick'em pool shows Pick'em + Rules & Settings, not Survivor/Margin). Commissioner-owned view keeps Rules & Settings.
6. **Correct the Global Standings card scope/label** on the homepage: either scope it to this Pool and label it "Pool Standings", or make it the pool-type-global leaderboard and label it as such. Pick per card; no "Global" label on pool-local data.

### Phase 2 — Member Record roster + Payments + Aggregate stats (must-ship, ADR 0003 revised)
7. **`reconcileMembership(poolId, uid, tx)` helper — ship first, coverage enforced by tooling.** The sole writer of membership across `participantIds`, `participations`/`joinedPools`, and Member Records (`pools/{id}/members/{uid}`). **Recomputes** the uid's membership + units from authoritative Pool state inside each write's own transaction (not add/remove) so multi-entry delete and partial squares release resolve right. **Completeness is a mechanism, not a hand-list:** (a) a grep audit enumerates every current writer of `participantIds`/`participants`/`propCards`/entry ownership; (b) each is routed through, rewritten to use, or retired in favor of `reconcileMembership`; (c) a test/CI guard fails the build if membership state is mutated anywhere else. Known writers to route/retire: NFL join, Bracket join (`bracketPools.ts:235`) **and `createBracketEntry` arrayUnion (`bracketEntries.ts:102`)**, **Playoff add via `submitPlayoffPicks` (`playoffPools.ts:137,213`)**, Squares claim/release + **auto-release (`reminders.ts:318,339`)**, both guest paths (`participant.ts:93,157`), owner seed (`poolCreation.ts:134`), **Props `purchasePropCard` (`propBets.ts:94,98`)**, legacy `syncParticipantIndices` (`participant.ts:225`) + `fixParticipantIds` (`poolOps.ts:532`), and all delete paths (`bracketEntries.ts:391`, `playoffPools.ts:340`). Owner gets a Member Record on Pool create; record carries `userName`, deterministic ID = uid.
8. **Member Record, not Entry.** Playable Entries are left exactly as each type models them (Bracket/Playoff stay multi-entry; Squares stays per-square). The Member Record holds membership + `paidStatus` + `memberReportedPaid` claim + Squares `unitsOwned/unitsPaid` + rebuy `rebuyOwed/rebuyPaid`. `submitNFLPicks` is unchanged as the Entry writer. **Props is brought into the model:** `purchasePropCard` today writes only `propCards`/`entryCount` and no participation — it gains a participation + Member Record write (via `reconcileMembership`) so Prop members appear on the Roster and in "My Entries" like every other type.
9. **Backfill migration (all types) — resumable, checkpointed, gated.** Create a Member Record for every real uid in the union of `participantIds` ∪ `participants` ∪ `entries` ∪ **`propCards`** (Props members live only in `propCards`), **skipping the `"guest"` sentinel** (its dues roll into the `rosterSummary` guest bucket); copy existing `paidStatus`, never overwrite. Invariant report adds `propCard-member-without-record`. Emit post-run invariant counts (participantId-without-member, member-without-participantId, guest-skipped, per-type failures). `rosterSchemaVersion` flips **per Pool only after that Pool's invariants pass**; a Pool with any failed invariant keeps the old read path. Staged; dry-run + report reviewed before any prod run.
10. **One authorized `setPaidStatus` callable**, Member Record mutation + payment-ledger append + `rosterSummary` update in a single transaction. Commissioner/Super Admin only for `paidStatus`. Remove all four direct-client payment writes (`NFLManagerView.tsx:195`, `NFLManagerBentoDashboard.tsx:97`, `BracketPoolDashboard.tsx:323`, `SuperAdmin.tsx:179`). Members may set only their own `memberReportedPaid` claim; Firestore rules **pin the exact diff** — only `memberReportedPaid`/`memberReportedAt` may change, `paidStatus`/`unitsPaid`/`rebuyPaid`/all else denied to Members. Each claim audited.
11. **`rosterSummary` projection + member read path.** `pools/{id}/rosterSummary` (member count, Dues Collected, Dues Expected, paid/unpaid, + derived guest/unclaimed-squares dues bucket), **readable only by the Pool's Members/Commissioner/admins**, **updated in the same transaction as every membership/payment mutation**. Lets `PaymentsPanel` show an honest pot pre-lock without exposing raw entries (rules block that until LOCKED). Commissioner mark-paid roster and member view both read Member Records.
12. **Commissioner Aggregate Stats Cloud Function**, triggered **only on Member Record writes** (not Entry pick/score writes). Per-type adapters for member count, **Dues Collected** (`paidStatus==='PAID'`), **Dues Expected** (fee × members, Squares via units), Payouts; **rebuy dues read from `rebuyOwed/rebuyPaid` on the Member Record** (written in the rebuy transaction, so numbers refresh). **Payouts are sourced from the winners subcollection / payout ledger, and the aggregate also refreshes on payout (`pools/{id}/winners/*`) writes** (`poolOps.ts:504`) — Member-Record-only triggering would leave Payouts stale. The aggregate **and `rosterSummary`** also refresh on **pool-doc writes that change inclusion-predicate fields** (`status`, `closedVia`, archived) **or fee fields** (`entryFee`, `costPerSquare`, `rebuyCost`) — a pool crossing the include/exclude boundary, or a fee edit via `updatePoolSettings`, must not leave counts/dues/payouts stale (Dues Expected = fee × members). Fix the `statsTrigger` `playoff_entries`→`pool.entries` source bug in the same pass. Only Pools passing the shared inclusion predicate (step 13) count. "Revenue" → "Dues Collected / Dues Expected" everywhere on commissioner surfaces.
13. **One shared pool-inclusion predicate** used by rosters, stats, and hub: exclude `COMPLETED`, `archived`, `CANCELED`, `closedVia:'ADMIN_CLOSE'`, `sim-*`. Replace the ad-hoc COMPLETED/archived filter in `GlobalCommissionerDashboard.tsx:23`.
14. **Rules & Rulesets editing** for the Commissioner, locked at first game of the season. `NFLPoolRules` gains an edit mode (owner/manager only) writing through `updatePoolSettings` (ADR 0001), disabled once `now >= earliest kickoff`. Read-only display otherwise.
15. **Canonical user-pool index for the nav split.** Pick one index (`participations`) as the source for "My Entries" (Pools the User is a Member of, filtered off membership not ownership); backfill Bracket's `joinedPools` onto it. "Manage My Pools" reads owned/managed Pools.

## Key decisions & tradeoffs
- **A dedicated Member Record (`pools/{id}/members/{uid}`) as the cross-type Roster/payment truth** — see [ADR 0003](docs/adr/0003-unified-pool-roster-model.md). The original "one Entry per Member" draft was rejected in adversarial review (collides with Bracket/Playoff multi-entry, can't model Squares per-square money, would put the play-gating `paidStatus` under member control). The Member Record leaves playable Entries untouched.
- **`paidStatus` stays commissioner/server-authoritative; member self-report is a separate `memberReportedPaid` claim** that never gates play — because Bracket already gates submission on `paidStatus==='PAID'`.
- **`reconcileMembership` is the sole membership writer**, shipped before the backfill, so `participantIds` and the Roster don't drift on join/leave/delete/release.
- **Aggregate stats via a Cloud Function triggered on Member Record writes only** (not Entry pick/score writes, which churn constantly); per-type dues adapters including rebuys; the never-written `managerStats` blob dies.
- **Dues Collected = fees marked PAID (+ rebuy dues); Dues Expected = fee × members (Squares via units).** No "Revenue" wording on commissioner surfaces — Entry Fees are peer-to-peer; the platform never holds the money (memory: stripe-commissioner-only).
- **`rosterSummary` projection** gives members a pre-lock honest pot without exposing raw entries (current rules block entry reads until LOCKED).
- **One shared pool-inclusion predicate** (exclude COMPLETED/archived/CANCELED/ADMIN_CLOSE/sim-*) used by rosters, stats, and hub.
- **Redesign both Homepage and Roster Hub**, all types, toward the mockup.
- **Overnight = commit + stage; Kevin deploys/migrates in the morning.** No prod function deploy or prod migration while unattended; migration ships with a dry-run + invariant report to review first.

## Risks / open questions (morning list candidates)
- Backfill migration against prod data needs a dry-run + invariant report + Kevin's go before it runs. Exact `npx firebase` deploy + migration commands staged for the morning (memory: deploy-commands).
- `reconcileMembership` must land and be wired into *every* membership path before the backfill, or the Roster drifts again; the audit of write paths (join/leave/delete/release/guest-claim across 5 files) is the gating task for Phase 2.
- Member-writable `memberReportedPaid` claim + new `members`/`rosterSummary` reads need a Firestore rules change; rules must deny member writes to `paidStatus` and scope claim writes to own record. Rules review required before deploy.
- Squares onto the Member Record is the largest surface; if it threatens the timeline, ship Member Record + summary + `setPaidStatus` for NFL first and put Bracket/Playoff/Squares behind the per-type adapters (rollout order only; model unchanged).
- Redesign visual direction: the mockup is NFL-flavored; other-type homepages need equivalent-but-not-identical card sets — may need a quick design check.

## Out of scope

- Running migrations against prod or deploying Cloud Functions to prod overnight.
- Super-Admin dashboard (separate plan) except where a shared component is reused.
- Onboarding/auth/password-reset flows except where they surface on the reviewed dashboards.
