### 2c. Run the `publishedWeeks` backfill — DRY RUN FIRST

**What it is for.** The new `extendWeekDeadline` guard refuses to extend a week
whose results members have already seen. It reads `pool.publishedWeeks.{week}`, a
marker only the auto-scorer writes and only from this release onward. Weeks you
scored MANUALLY before today have no marker, so the guard does not fire on them.
This backfill stamps those weeks.

**It is not urgent and nothing is worse than yesterday until you run it** — an
unmarked legacy week is exactly as extendable today as it was last week. But run
it before arming the auto-scorer.

**There are two buttons for it** in SuperAdmin → **Operations**, added by this PR
(they only appear after the Coolify rebuild in Step 4 above):

1. Open <https://marchmeleepools.com> and sign in as SUPER_ADMIN.
2. Go to **SuperAdmin → Operations**.
3. Click **"Backfill Published Weeks (dry run)"**. It writes nothing. It pages
   through every NFL pool in one click and shows the accumulated report.
4. Read the report before doing anything else — see the checklist below.
5. When it looks right, click **"Backfill Published Weeks"** (the non-dry-run
   one). It is marked destructive, so it will ask you to confirm.

**What to check in the dry-run report before going live:**
- `poolsScanned` — how many NFL pools it looked at.
- `poolsChanged` / `weeksMarked` — how many pools/weeks it WOULD stamp.
- `plannedWrites` — a per-pool list of `{ poolId, weeks }`. Read a few and
  confirm those weeks really were scored (SuperAdmin → the pool → standings).
- `failures` — should be empty.

(The button loops all pages itself, so there is no cursor for you to manage.)

Every run, dry or live, also writes an `admin_audit` entry with
`action: "BACKFILL_PUBLISHED_WEEKS"`, so you can read it in
**SuperAdmin → Admin Audit Log** instead of scrolling the console.

**When the dry-run report looks right**, re-run with `dryRun: false`. It is
idempotent — a second live run reports `poolsChanged: 0`.

## 3. What shipped in #279, in brief

Five things, all from `PLAN-REALTIME-SCORING.md` §3a/§4:

1. **The fenced scoring lease** `pool.autoScore.scoringLease = { owner, until }` —
   the mutex across the scheduled job, the manual "Score Week" button and the
   finalize sweep. Every write asserts owner + expiry + `lockRevision` inside the
   transaction that commits it.
2. **`pool.settings.lockRevision`**, monotonic, bumped by `extendWeekDeadline` and
   by any lock-affecting settings save.
3. **The `extendWeekDeadline` publish guard** + the cold-start backfill above.
4. **Server-only scorer fields**: `firestore.rules` protects `publishedWeeks` /
   `autoScore` / `scoredWeeks` / `scoredThroughWeek` / `type` and denies a
   client-direct `settings` write on NFL pools; `NFLManagerView` routes through a
   merge-preserving `updatePoolSettings`.
5. **The per-entry submission watermark** on `submitNFLPicks` / `proxyPick` /
   `executeSurvivorRebuy`, folded into the scorer's skip decision as a monotone
   sum.

Baselines moved: functions unit **1004 → 1048**, emulator **177 → 187** pass
(10 skipped, unchanged), root vitest **291 → 301**. Both typechecks clean, both
audits clean.
